## 关键收获

### Week 2 任务：Agent Profile 与能力声明草图

完成了 **Research Report Agent** 的完整 Profile 设计，输出到 `tasks/week_2/agent_profile.md`，涵盖 12 个维度：

| # | 模块 | 要点 |
|---|------|------|
| 1 | Identity | 学习 demo agent，用于生成带证据链的结构化研究报告 |
| 2 | Capability | 9 项能力：主题理解、资料搜索、阅读、摘要、声明提取、引用映射、报告生成、缺口检测、人工审核支持 |
| 3 | 输入/输出 | 标准化 JSON schema，支持 topic/goal/depth/source_preference/constraints 等参数 |
| 4 | 协作对象 | 拆分为 5 个子 agent：Search / Reader / Verifier / Writer + Human Reviewer |
| 5 | 调用方式 | 三种接口：自然语言、REST API、A2A agent-to-agent |
| 6 | 收费设计 | Demo credits 模式（每次任务 5-15 credits），不接真实支付 |
| 7 | 验证机制 | 三层验证：格式验证 → 来源验证 → Claim 验证，带 confidence 评级 |
| 8 | Reputation | 7 项指标：完成任务数、失败率、评分、引用准确率、无来源结论率等 |
| 9 | 失败处理 | 10 种失败场景的标准化处理策略，含失败响应 JSON schema |
| 10 | 完整 Profile JSON | 合并以上所有维度的完整 Agent Profile 草图 |
| 11-12 | MCP vs A2A | MCP = agent 连接工具；A2A = agent 之间协作。单 agent 跑通后再引入 A2A |

**核心理解：**
- MCP 解决 "agent 怎么用工具" → 搜索、读文档、检查引用
- A2A 解决 "agent 怎么和其他 agent 分工" → Search/Reader/Verifier/Writer 流水线
- Agent Profile 是 agent 的「身份证 + 能力声明」，包含输入输出契约、失败边界、信誉体系
