## 学习笔记

### 任务：链上地址风险分析任务市场 — Payment/Commerce Flow 拆解

**场景**：用户让 Agent 下单购买地址风险分析报告，预算 ≤10 USDC，10 分钟返回。

**六角色模型**：Client → Provider → Evaluator → Payer → Arbitrator → Recorder

**完整 8 步流程**：
1. 预算授权（用户不把钱包完全交给 Agent，而是创建任务级授权）
2. 服务发现（通过 ERC-8004 查询 Provider Agent 身份与声誉）
3. 报价（Provider 返回报价 + 交付标准）
4. Escrow 锁定资金（参考 ERC-8183 job-based escrow）
5. 执行任务（Provider 查询链上数据、黑名单、资金流分析）
6. 交付（完整报告存 IPFS，哈希上链）
7. 验收（Evaluator 按 8 项标准自动验收）
8. 付款 / 退款 / 争议（三档争议机制）

**协议对比**：
| 协议 | 定位 | 适合 |
|------|------|------|
| x402 | 支付入口 | API 级即时付款 |
| MPP | 机器间支付协调 | 高频微支付 session |
| ERC-8004 | Agent 身份/发现/声誉 | 信任入口层 |
| ERC-8183 | Job+Escrow+Evaluator | **commerce kernel** |

### 活动：Cobo Agentic Wallet

**核心命题**：当 Agent 需要金钱操作时，信用就成了基础设施。

**Cobo 信任设施三板斧**：
- **MPC 分片**：Cobo、Agent、用户三方各持私钥分片，2/3 签名才可执行
- **Pact 授权协议**：Intent（目标）+ Execution Plan（路径）+ Policies（风控：预算/代币/链限制）+ Completion Conditions（终止条件）
- **Recipe**：预加载知识库 + 操作指引，类似 Agent skill

**与任务设计的关联**：任务中的「预算授权」步骤（任务级授权而非全权委托），正是 Cobo CAW 的核心场景——钱包层解决预算、权限边界、风控策略和审计记录问题。

## 关键收获

> **Agent Commerce 的信任链 = 链下意图授权（Cobo Pact）+ 链上 Escrow 结算（ERC-8183）+ 自动化验收（Evaluator）+ 分档争议仲裁。**

三条核心认知：
1. **报价必须包含交付标准** — 否则付款只是转账，无法形成 commerce
2. **链下意图 + 链上结算** 是务实路径 — Cobo Pact 管"能做什么"，ERC-8183 管"钱怎么走"
3. **争议机制要分层** — 小额自动复验 / 中额多 Agent 投票 / 大额人工仲裁，不要一开始做复杂 DAO
