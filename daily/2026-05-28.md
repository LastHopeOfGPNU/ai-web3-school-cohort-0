### 🛠️ Week 2 任务完成

**x402 Paywall + CAW Agent 自主支付闭环** `experiments/x402-caw-agent-loop`

搭建了一个最小化的 agent commerce 支付闭环 demo，核心链路：

```
Agent 请求 API → 402 Payment Required → Pact 校验预算/链/合约 → 付款重试 → Settlement + 审计 → 返回结果
```

**实现架构（9 个源文件，纯 Node.js ESM）：**

| 文件 | 职责 |
|------|------|
| `src/server.js` | x402-style paywall：未付款返回 402 + PAYMENT-REQUIRED header |
| `src/http-server.js` | 本地 HTTP 服务入口 |
| `src/pact.js` | CAW/Pact 策略层：预算上限、单笔限额、允许链、允许合约、有效期 |
| `src/http-agent.js` | HTTP agent：自动识别 402，解析付款要求，带签名重试 |
| `src/agent.js` | 进程内 agent 闭环 |
| `src/audit.js` | 审计日志：pact_created → pact_check → payment_signed → payment_settled |
| `src/money.js` | 金额格式化（USD ↔ microusd） |
| `src/demo.js` / `src/http-demo.js` | 进程内/HTTP demo 入口 |

**Pact 策略校验（6 层拒绝）：**
1. `pact_expired` — 超过有效期
2. `network_not_allowed` — 链不在白名单
3. `contract_not_allowed` — 合约/收款方不在白名单
4. `amount_exceeds_budget` — 累计超出预算
5. `amount_exceeds_per_payment_limit` — 单笔超限
6. 全部通过 → 生成签名 payload

**审计事件链：** `pact_created` → `pact_check(allowed|denied)` → `payment_signed` → `payment_settled`

## 关键收获

1. **x402 协议本质**：不是新支付网络，而是在 HTTP 层定义了 "402 Payment Required" + base64url header 的付款协商格式。服务端返回付款要求，客户端识别后付款重试，简洁但有效。

2. **Pact 才是 Agent Commerce 的核心差异**：没有 Pact 的 agent 付款就是普通自动转账。Pact 把 Intent、Execution Plan、Policies（预算/链/合约/时间）和 Completion Conditions 绑在一起，agent 只能在边界内操作——这和 Week 1 学的 Cobo CAW 架构完全对应。

3. **审计是基础设施，不是事后补丁**：实验里每个付款环节都有对应审计事件（pact_created → check → signed → settled/aborted）。真实系统中如果缺少这一步，agent commerce 的信任基础就塌了。

4. **从概念到代码的跨越**：Week 2 前两个任务（agent_profile、payment_commerce_flow）是分析和设计，今天这一步把 "402 → Pact → Payment → Settlement" 跑成了可执行的 Node.js 闭环。下一步可以接入真实 CAW API。

5. **Week 1 任务盘点**：用 WCB API（tasks.myTaskHistory）全量扫描了 37 个 Week 1 任务，17 个 APPROVED，15 个未提交——核心缺口在 Web3 实战（测试网交易、合约部署）和概念卡片输出。
