## 💡 关键收获

1. **任务推进方法论（Co-learning）**：拆任务 → 整 proof → 转问题为行动，持续迭代。将 Week 3 的支付相关任务拆成「Cobo WaaS 文档阅读 → 支付场景分析 → MVP 构思」三个小步骤，每步都能产出可展示的 PoW
2. **支付场景分析框架**：用户角色 → 支付环节痛点 → 链上方案 vs 传统方案 → MVP 边界。套用这个框架快速判断一个支付场景是否值得做
3. **AI Agent 支付的独特挑战**：Agent 触发支付跟人工支付的核心差异在于「谁来授权」和「信任边界」—— Agent 需要在无人干预下完成支付决策，这对钱包的权限模型和风控策略提出了不同要求
4. **Cobo WaaS 2.0 与支付场景的对接点**：
   - Custodial 钱包 → 适合平台级支付（如交易所内部结算）
   - MPC 钱包 → 适合 Agent 支付（分片共管 = 安全 + 自动化）
   - Smart Contract Wallet → 适合可编程支付流（条件支付、批量转账、Gas 代付）
5. **支付 MVP 的判断标准**：不是「能做完整支付链路」而是「能跑通一个最小支付场景并验证用户价值」，这和 Hackathon 的「可验证 MVP」思路一脉相承

## 🚧 遇到的问题

- Agent 支付中「授权阈值」如何设定？金额上限、频率限制、白名单地址的粒度需要根据场景权衡，没有通用答案
- Cobo WaaS 2.0 的 MPC User-Controlled 方案对纯后端 Agent 有集成复杂度，需要评估是否值得在 Hackathon 阶段引入
