### 1. LLM

**一句话解释：**
Large Language Model，也就是大语言模型，可以理解为一个基于大量文本训练出来的“语言预测与生成系统”，它擅长根据上下文生成合理的回答、代码、总结或推理过程。

**具体例子：**
我输入“帮我总结这篇文章”，LLM 会根据文章内容生成摘要；我输入“用 Python 写一个爬虫”，它也可以生成代码草稿。

**常见误区或边界：**
LLM 不是天然知道事实真相，它生成的是“看起来合理”的内容。如果问题涉及最新信息、法律、医疗、财务等高风险领域，需要外部检索、工具验证或人工复核。

### 2. Prompt

**一句话解释：**
Prompt 是给 AI 的任务说明，它决定 AI 要扮演什么角色、处理什么输入、按什么规则输出结果。

**具体例子：**
“你是一个产品经理，请把下面的聊天记录整理成 PRD，包含用户角色、功能列表、优先级和风险点。”这就是一个比较明确的 prompt。

**常见误区或边界：**
Prompt 不是魔法咒语。模型能力、输入资料质量、任务复杂度都会影响结果。对于复杂任务，单次 prompt 往往不如“分步骤输入 + 中间检查 + 迭代修改”稳定。

### 3. Context Window

**一句话解释：**
Context window 是模型一次对话中能“看见”和处理的信息范围，包括用户输入、历史对话、系统规则和工具返回结果。

**具体例子：**
如果我把一份长文档发给 AI，让它总结前后逻辑，模型只能基于当前上下文窗口中实际可见的内容进行处理。

**常见误区或边界：**
上下文窗口变大不代表模型一定理解得更好。信息太多、结构太乱时，模型可能忽略关键细节，所以长文档最好先分块、加标题、标注重点。

### 4. Workflow

**一句话解释：**
Workflow 是把一个任务拆成多个固定步骤，让 AI 或系统按流程完成，而不是每次都临时发挥。

**具体例子：**
做一篇小红书内容，可以设计成：选题分析 → 生成标题 → 写正文 → 生成封面文案 → 检查违规风险 → 输出发布版本。

**常见误区或边界：**
Workflow 适合流程相对稳定的任务。如果任务目标经常变化、判断标准很模糊，过早设计复杂 workflow 可能会增加成本，反而降低效率。

### 5. Agent

**一句话解释：**
Agent 是能围绕目标自主规划步骤、调用工具、观察结果并继续行动的 AI 系统。

**具体例子：**
一个浏览器 Agent 可以接收“帮我查找某个产品的竞品信息”，然后自动打开网页、搜索、读取页面、整理对比表。

**常见误区或边界：**
Agent 不等于完全自动化员工。它在复杂环境中可能会误判、卡住、重复操作或调用错误工具，所以需要权限控制、执行日志和人工确认节点。

### 6. Tool Use

**一句话解释：**
Tool use 是让 AI 调用外部工具来完成模型本身做不到或不稳定的事情，比如搜索网页、查询数据库、执行代码、读取文件、操作浏览器。

**具体例子：**
当 AI 不确定某个软件的最新版本功能时，可以调用搜索工具；当需要计算数据时，可以调用 Python；当需要查询订单时，可以调用后台 API。

**常见误区或边界：**
工具调用不能自动保证结果正确。工具可能返回过期数据、错误数据，或者 AI 可能理解错工具返回内容。因此关键任务要有结果校验和异常处理。
